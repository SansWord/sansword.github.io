Four inputs, four jumps

Every big improvement started with something I handed over: a fact about the message, a video, a paper, and then a second question about the same paper. The quotes are my actual prompts.

What I asked What Claude built

    The wall

    “I want you to guess it without correct setting. but I worry if that would be too expensive”

    Pulled the emulator’s JavaScript to get the exact rotor wirings, checked them with a round-trip test, then sized the problem honestly.

    A crib

    “the first 4 plaintext is "TEST", how fast you can do it now?”

    An exact-match filter across every rotor, reflector, ring, and start position, then a multi-core ranking of the survivors by English letter frequency. The answer was certain and unique.

    A video

    “I've watched this youtube video discussing how to bracking enigma, would the strategy mentioned in the video makes it easier?”

    Read the Computerphile transcript and built a ciphertext-only attack in stages: find rotors and start position first, then ring settings. It needs 200+ letters and no crib. Its weak spot: a correct ring search still took minutes.

    The paper behind the video

    “the video is introducing this paper: [link] would that give you any insight to improve our script?”

    Implemented James Gillogly’s 1995 ring recovery: move the ring setting and the start position together, 26 trials per rotor. It found the right rotors and readable English in 0.014 s, cheap enough to check every candidate. On one test, a few letters near rotor turnovers still differed from the exhaustive search.

Scoring “almost English”

Enigma leaks. A decryption with only some settings right already looks measurably more like English than one with everything wrong. With a score for that, one impossible search becomes three small ones: rotors, then rings, then the plugboard.

  1. 4,394,000rotor orders × start positions, ranked by IoC
  2. 52ring trials per candidate, ranked by IoC
  3. ~1,295plugboard swaps, ranked by trigrams

Three scores, each where it pays off

ScoreWhat it noticesUsed to rankCandidates
Chi-squared Which letters are common (E, T, A…) Crib survivors 1.29 M
IoC How uneven the letter counts are, whichever letters they are Rotors + start, then the ring sweep 4.4 M, then 52
Trigrams Real 3-letter sequences like THE, ING, ION Plugboard swaps ~1,295

Cheap scores for millions of candidates, the sharper and slower score for the last handful.

When IoC gets fooled

On a message with no plugboard at all, IoC scoring added two fake plugs because they nudged the score up from 0.0618 to 0.0638. Trigram scoring correctly found zero.

Two lessons

“This journey started with my interest in and curiosity about Enigma after watching the video. It taught me more about the Enigma machine itself. More importantly, it taught me how to guide Claude to implement what I learned, using Claude to quickly turn the information I found into working code.” Me, looking back on the project

Curate the knowledge, let Claude implement it

“provide what I learn from YT, paper so claude can use it to implement it”
  • videobecame the staged, ciphertext-only attack
  • paperbecame 52-trial ring recovery, the biggest speedup
  • paper, againfixed the plugboard stage and a real scoring bug

My part was judgment: which source was worth reading, and when a source deserved a second, narrower look. A source is rarely used up after one read. A new question can pull something new out of it.

Partial correctness has a score

“from brute force to partially solve the code. and using a proper scoring system to rank the partial result.”

More hardware would never have covered 1020 settings. What broke the wall was a score that rewards getting some settings right, which let each stage be solved and ranked on its own. Picking the right score for each stage mattered as much as the search itself.

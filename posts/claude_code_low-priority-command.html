# 狀態列會顯示剩餘 allowance 與自動結束時間： Lower priority until 4pm · 62% allowance left · /low-priority to stop

三種狀態皆為實機輸出：指令說明、未達上限、以及已啟用。此功能上線時間晚，官方文件尚未收錄，以下區分「已驗證」與「待確認」。

已驗證　CONFIRMED
何時可用 · WHEN
要等到所有付費路徑都用完或關閉才會啟用 —— 只要還有 extra usage 額度且未關閉，系統會先自動用它。上方仍有額度時執行只會回覆「現在不可用」。
作用 · WHAT
不必停下來等重置，而是立刻繼續工作 —— 改由閒置的餘裕算力供應，因此回應可能暫停等候，直到 session 視窗重置。
邊界 · LIMITS
只解除 session（5 小時）那道牆 —— 每週上限仍然有效。session 重置後自動結束，無需手動關;或再執行一次即停止。

來源：Claude Code CLI 內建說明字串，加上分享者實機測試輸出。

觸及上限後的兩種選擇　YOUR OPTIONS AT THE LIMIT

停下等待

等 session 視窗重置後再繼續。預設行為，零成本，但工作中斷 —— 長任務、跨夜跑批時最痛。
代價：時間

/low-priority

不必等重置，立刻繼續，但請求以較低優先權排隊，回應可能較慢。前提是前面的付費路徑已用完或關閉。
代價：速度 / 優先權

驗證方式：啟用後觀察狀態列的 allowance left % 如何隨用量下降、何時回補，並比對 /usage 是否有任何項目被扣。

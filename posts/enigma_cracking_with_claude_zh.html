起點：Enigma 模擬器產生的 56 個字母，沒有任何設定。

從 1020到 4.4 秒

我和 Claude 一起破解 Enigma 學到的事。資料是我找的：一支 YouTube 影片、一篇 1995 年的研究論文。Claude 讀懂它們，再把每一份都寫成能跑的程式。

Claude 本身沒有解密任何東西。它寫的是攻擊密文的 Python 腳本，海報上的每一個時間，都是這些腳本在我 14 核心筆電上實際執行的結果。

四次輸入，四次進步

每一次大幅進步，都從我交給 Claude 的一樣東西開始：一個關於訊息的已知事實、一支影片、一篇論文，以及針對同一篇論文的第二個問題。引號內是我當時實際輸入的提示，原文是英文，下方附上原句。

我的提問 Claude 的實作

    高牆

    「我想請你在不知道正確設定的情況下猜出來，但我擔心這樣會不會太花成本。」

    一段已知明文

    「前 4 個明文字母是『TEST』，現在你能多快解出來？」

    “the first 4 plaintext is "TEST", how fast you can do it now?”

    對所有轉子、反射器、環設定與起始位置做精確比對篩選，再用多核心依英文字母頻率替留下的候選排序。得到的答案確定而且唯一。

    “I've watched this youtube video discussing how to bracking enigma, would the strategy mentioned in the video makes it easier?”

    讀了 Computerphile 影片的逐字稿，做出分階段、只靠密文的攻擊：先找轉子與起始位置，再找環設定。需要 200 個以上的字母，但不需要已知明文。弱點是要正確找出環設定，仍得花好幾分鐘。

    4,394,000
    第一階段耗時
    約 4 秒
    環設定暴力搜尋
    4.7 分鐘

    影片背後的論文

    「影片介紹的是這篇論文：[連結]　它能不能給你一些改進我們腳本的想法？」

    “the video is introducing this paper: [link] would that give you any insight to improve our script?”

    實作 James Gillogly 1995 年的環設定還原法：讓環設定和起始位置一起移動，每個轉子只試 26 次。0.014 秒就找出正確的轉子和可讀的英文，便宜到可以檢查每一個候選。不過在一次測試中，轉子進位附近仍有幾個字母和暴力搜尋的結果不同。

    同一篇論文，換個問題

    「你可以實作論文裡提到的接線板改進嗎？」

    “can you implement the plugboard upgrade from the paper?”

    帶著更具體的問題重讀，找到第一次漏看的細節：用英文三字母組（trigram）替接線板的猜測評分。接著用貪婪搜尋找出每一對接線，沒有任何交換能再改善時就自動停下，所以每則訊息都能直接跑。

替「接近英文」打分數

Enigma 會洩漏線索。只猜對部分設定時，解出來的文字就已經比全部猜錯時明顯更像英文。只要能替這件事打分數，一個不可能的搜尋就變成三個小搜尋：先轉子，再環設定，最後是接線板。

  1. 4,394,000轉子順序 × 起始位置，用 IoC 排序
  2. 52每個候選的環設定嘗試，用 IoC 排序
  3. ~1,295接線板交換，用三字母組排序

三種分數，各用在划算的地方

評分方式看的是什麼用來排序候選數量
卡方檢定 哪些字母常見（E、T、A…） 已知明文篩選後的候選 129 萬
重合指數 IoC 字母出現次數有多不平均，不管是哪些字母 轉子與起始位置，接著是環設定掃描 439 萬，再來 52
三字母組 真實的三字母序列，例如 THE、ING、ION 接線板交換 ~1,295

候選數以百萬計時，用便宜的分數；只剩少數候選時，才換上更準也更慢的分數。

IoC 被騙的時候

在一則完全沒有接線板的訊息上，IoC 評分卻加了兩對假接線，只因為它們讓分數從 0.0618 微升到 0.0638。三字母組評分則正確判斷出 0 對。

正確INCRYPTOGRAPHYA
假接線INCQYPTOGQAPLYA

兩個收穫

「這趟旅程起於我看完影片後，對 Enigma 的興趣與好奇。我因此對 Enigma 機器本身有更多了解，但更重要的是，我也因此學會怎麼引導 Claude 實作我學到的東西，透過 Claude 快速實作我找到的資訊。」

我自己，回顧這個專案

我整理知識，Claude 負責實作

「把我從 YouTube 和論文學到的東西交給 Claude，讓它拿去實作。」

“provide what I learn from YT, paper so claude can use it to implement it”

  • 影片變成分階段、只靠密文的攻擊
  • 論文變成只要 52 次嘗試的環設定還原，整個專案最大的加速
  • 再讀論文修好接線板階段，也修掉一個真實存在的評分 bug

我負責判斷：哪份資料值得讀，以及什麼時候該帶著更具體的問題再看一次。一份資料很少讀一次就用完，換個新問題，常常能再挖出新東西。

部分正確，也能打分數

「從暴力破解，走到部分解開密碼，再用合適的評分系統替部分結果排序。」

“from brute force to partially solve the code. and using a proper scoring system to rank the partial result.”

再多硬體也跑不完 1020 種設定。真正打破高牆的，是一個「猜對一部分就加分」的評分方式，讓每個階段都能各自求解、各自排序。替每個階段選對分數，和搜尋本身一樣重要。

花了多少 token 額度

~58%（Claude Pro 的 5-hr session，整個開發過程）

數字來自開發過程的對話紀錄：把每一次 API 呼叫的 token 依價格加權，再以 Claude Pro 用量表顯示 35% 的那一段為基準換算。Anthropic 沒有公開用量上限如何計算各種 token，所以這仍是估計值。

“Test if Claude can decrypt an Enigma machine and how fast it can do it”

意思是：「測試 Claude 能不能解開 Enigma 機器，以及它能多快做到。」已知明文攻擊在 14 核心上花了 4 分 22 秒解出。正確解密的卡方值是 21.6，遠遠領先第二名的 76.2。
